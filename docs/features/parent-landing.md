# Страница для родителей: лендинг из руководства

Адрес: https://mziko.smartagency.online/about/. Одна страница: шапка с кнопками
«Написать боту» и «Как начать», три карточки «как это устроено» и полное
руководство для родителей с оглавлением. Старый адрес на GitHub Pages
(kkc-group.github.io/mziko) перенаправляет сюда.

## Один источник текста

Текст страницы не пишется руками: это `docs/general/parent-guide.md`,
отрендеренный в `site/template.html`. Правило проекта требует править
руководство в той же ветке при любом изменении, которое видят родитель или
ребёнок, поэтому страница обновляется вместе с приложением без отдельного шага.

Из руководства берутся:

- первый абзац как текст шапки, остальные абзацы до первого раздела как
  вводка над руководством;
- каждый `## N. Заголовок` как карточка с номером; каждый `###` получает якорь
  `sN-k` и строку в оглавлении;
- цитаты (`>`) как диалоги с ботом: `**Вы:**` и `**Бот:**` открывают
  сообщение, строки `*[кнопка]*` становятся кнопками под ним, варианты в
  обратных кавычках после `*[подпись:]*` строкой настроек с отмеченным `✓`;
  приставка `кнопка:` из подписи убирается; строки, перенесённые в markdown по
  ширине 80 символов, склеиваются обратно (длинная строка без точки в конце
  продолжается на следующей);
- таблицы: команды бота, монеты и программа узнаются по первому заголовку
  («Команда», «Что случилось», «Раздел»); программа на телефоне складывается
  в карточки по разделам;
- блоки `<div class="shots">` со снимками: каждая картинка получает рамку
  устройства с настоящими пропорциями из заголовка PNG;
- грузинский текст оборачивается в `.ka` для грузинского шрифта.

Шапка, три карточки и подвал живут в шаблоне. Адрес бота в кнопке
«Написать боту» задаётся константой `BOT_URL` в `scripts/build_site.py`.

Сборка падает, а не публикует дыру, если в руководстве нет разделов `## N.`,
если снимок из `parent-guide/` не найден, или если диалог не встал на место.

## Как собирается и публикуется

- Локально: `make site` кладёт готовую страницу в `_site/` (в `.gitignore`);
  открыть `_site/index.html`. Дата «Обновлено» в подвале берётся из последнего
  коммита, задевшего руководство.
- В образе: `frontend/Dockerfile` отдельным шагом на Python запускает тот же
  скрипт и кладёт `_site/` в `/srv/about`. Для этого `.dockerignore` возвращает
  в контекст сборки руководство со снимками, шаблон и скрипт. В образе нет git,
  поэтому дата в подвале равна дате сборки образа, то есть деплоя.
- На сервере: Caddy (`deploy/Caddyfile`) отдаёт `/about/*` из `/srv/about`
  без кэша и перенаправляет `/about` на `/about/`. Приложение (PWA) добавило
  `/about` в исключения сервис-воркера (`navigateFallbackDenylist` в
  `frontend/vite.config.ts`): иначе браузер, где приложение уже открывали,
  показывал бы на `/about` главный экран ребёнка вместо страницы.
- Обновление: любой пуш в `main` пересобирает образ `web` и перезапускает
  сервер (`.github/workflows/deploy.yml`), страница обновляется вместе с ним.
- GitHub Pages: `.github/workflows/pages.yml` выкладывает только
  `site/pages-redirect/index.html`, редирект на новый адрес, и запускается,
  когда меняется этот файл.

## Что изменилось

- Страница переехала с GitHub Pages под основной домен, `/about/`.
- Прототип «Цвета» без сервера удалён вместе с адресом `/poc/`: он был нужен
  до появления настоящего приложения.
- `README.md`: абзац про страницу и строки `deploy/Caddyfile` и `site` в
  составе. Ссылка в руководстве ведёт на новый адрес.

## Что за бортом

- Отдельные страницы на раздел: всё руководство на одной странице.
- Три карточки «как это устроено» написаны в шаблоне, а не берутся из
  руководства: при смене вводных фраз их надо поправить руками в
  `site/template.html`.
- Проверка сборки страницы в CI до мержа: она проверяется сборкой образа
  `web` в `deploy.yml`, то есть уже после пуша в `main`.
