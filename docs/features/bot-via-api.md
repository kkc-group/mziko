# Бот ходит в API, а не в базу

Документ отвечает на «как устроено» тому, кто код не писал. Что менялось,
видно в `git log`.

## Что изменилось

Раньше Telegram-бот и API были двумя процессами с одной базой: бот звал те же
сервисы, что и API, напрямую, минуя HTTP. Правила про монеты и недели лежали
в одном месте, но граница держалась только на честном слове: любая новая кнопка
в боте могла написать запрос к таблице.

Теперь у данных одна дверь. Бот — такой же клиент API, как приложение ребёнка:
он ходит по HTTP под префиксом `/api/parent`, представляется общим секретом и
называет, от чьего имени действует. В его контейнере нет адреса базы, и он не
импортирует ни моделей, ни сервисов, ни SQLAlchemy — это проверяет тест.

Для родителя ничего не поменялось: те же команды, те же кнопки, тот же
воскресный отчёт. Один нюанс: кнопка «Отключить» у уже отключённого устройства
теперь отвечает «Недоступно», а не молча.

## Как это работает

- **Секрет и родитель.** В `.env` живёт `BOT_API_TOKEN`, одинаковый у `api` и
  `bot`. Бот шлёт его в `Authorization: Bearer`, а Telegram ID отправителя — в
  заголовке `X-Telegram-Id`. API (`app/api/deps.py`, `current_parent`) сверяет
  секрет и ищет родителя; чужой ID даёт 403, и бот на такое обновление молчит,
  как и раньше. Пустой секрет выключает родительские ручки целиком.
- **Первые родители** из `ADMIN_TELEGRAM_IDS` заводятся при старте API
  (`app/main.py`, lifespan), а не бота: базой владеет API.
- **Контракт** — `app/schemas/parent.py`: ребёнок с настройками, неделя с суммой
  к выплате, отчёт, прогресс по темам, код привязки, устройство, список отчётов
  на воскресенье. Там же варианты курса и лимита, которые API проверяет, а бот
  показывает кнопками. Бот импортирует только этот модуль и настройки процесса.
- **Ручки** — `app/api/parent_routes.py`:

  | Ручка | Что делает |
  |---|---|
  | `GET/POST /children` | список детей родителя, добавить ребёнка |
  | `GET /children/{id}/report?week_start=` | отчёт за текущую или заданную неделю |
  | `GET /children/{id}/progress` | прогресс по темам и словам |
  | `PATCH /children/{id}/settings` | курс, лимит, подсказка; чужие значения → 422 |
  | `POST /children/{id}/pair-codes` | код привязки с готовой ссылкой на 15 минут |
  | `GET /children/{id}/devices`, `DELETE .../devices/{id}` | устройства, отзыв |
  | `GET /weeks/{id}`, `POST /weeks/{id}/pay` | неделя по id с кнопки, «Выплачено» |
  | `GET /reports/due` | все дети с отчётами и Telegram ID родителей; только по секрету |

  Чужой ребёнок, неделя или устройство выглядят как несуществующие: 404.
  Выплата идемпотентна, повтор возвращает `already_paid`.
- **Клиент бота** — `bot/api.py`, класс `ParentApi` на httpx. Один экземпляр на
  процесс; middleware (`bot/middleware.py`) привязывает его к отправителю каждого
  обновления и переводит ошибки API в ответы: 403 — тишина, 404 — «Недоступно»,
  остальное — «Не получилось, попробуйте позже» и запись в лог.
- **Обработчики** (`bot/handlers.py`), тексты и клавиатуры работают со схемами
  контракта. Кнопка подсказки несёт целевое значение (`hint:0|1`), кнопка
  устройства — id ребёнка и устройства, чтобы боту не читать состояние перед
  действием.
- **Воскресный отчёт** по-прежнему живёт в боте (`bot/scheduler.py`): Telegram
  знает только он. Список «кому что слать» он берёт у `GET /reports/due`.
- **Docker.** У сервиса `bot` в compose `API_URL=http://api:8000` и пустой
  `DATABASE_URL`; он стартует после того, как `api` здоров. Локально без Docker:
  `make api`, затем `make bot` с `API_URL=http://localhost:8000` в `.env`.

## Тесты

- `tests/test_parent_api.py` — каждая ручка через HTTP, граница родителя,
  выплата дважды, обмен кода привязки через детскую ручку.
- `tests/test_bot.py` — клиент бота против настоящего приложения в процессе
  (ASGI, без сети), тексты и клавиатуры на схемах, и проверка, что в `bot/` нет
  импортов `app.models`, `app.services`, `app.core.db`, `sqlalchemy`.

## За бортом

- Бот и API собираются из одного образа `backend/`; у бота остаются лишние
  зависимости (SQLAlchemy, asyncpg). Разделение на два пакета — отдельный шаг,
  граница уже держится кодом.
- Обработчики aiogram не тестируются сквозь Telegram-объекты; покрыт клиент,
  ручки и форматирование.
