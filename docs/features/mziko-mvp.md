# Мзико MVP: как это работает

Документ отвечает на «как устроено» тому, кто код не писал. Что именно было
запрошено, лежит в [TASK.md](../../TASK.md); что менялось, видно в `git log`.

## Что умеет система

Ребёнок открывает Мзико на iPad как обычное приложение и за 5–7 минут проходит
занятие: три новых слова с картинкой и звуком, затем игры «Послушай и найди» и
«Вспомни слово» с новыми и старыми словами. За каждый верный ответ с первой попытки
падает монета, за слово, отвеченное верно в три разных дня, — ещё пять. В воскресенье
в 20:00 родителю приходит отчёт в Telegram с суммой в лари, он выдаёт наличные и
нажимает «Выплачено».

## Экраны (фронтенд, `frontend/src`)

- **Главный** (`screens/Home.tsx`): Мзико с приветствием, копилка с монетами и лари,
  семь кружков недели со звёздочками за дни с занятием, путь из уроков (см.
  [lessons.md](lessons.md)): пройденные свёрнуты, текущий — карточка с «показано
  X из Y» и кнопкой «Играть», следующие закрыты; наклейки (выученные слова
  цветные, остальные серые).
- **Занятие** (`screens/Lesson.tsx`): полноэкранное, сверху крестик, прогресс и
  мини-копилка. Шаги `intro` (карточка), `listen` (4 картинки), `recall` (3 слова с
  озвучкой каждого). Верно: зелёная подсветка, прыжок Мзико у тоста, монеты летят в
  копилку. Неверно: красная тряска, вариант блокируется, ребёнок пробует ещё. Итог:
  «Ура, занятие готово!», монеты за занятие, новые наклейки, «Домой».
- **Вход** (`screens/Login.tsx`): экран ввода постоянного кода ребёнка или
  ссылка `/c/<код>` из бота; см. [child-code-login.md](child-code-login.md).

Звук: файл `/media/audio/<тема>/<slug>.mp3`, предзагружается при старте занятия
(и разблокируется для iOS в том же нажатии). Файла нет — синтез речи: грузинский
голос, иначе русский по кириллической подсказке. Ответы уходят на сервер сразу; при
сетевой ошибке повтор с тем же `client_answer_id`, после четырёх неудач — тост
«Нет связи» с кнопкой «Повторить».

PWA: манифест с иконкой Мзико, сервис-воркер кэширует оболочку и аудио, `/api` не
кэшируется никогда. Тёмная тема, `prefers-reduced-motion`, safe-area, портрет и
альбом.

## Ручки (бэкенд, `backend/app/api/routes.py`)

| Ручка | Что делает |
|---|---|
| `POST /api/login`, `GET /api/login/status` | Вход по коду ребёнка и статус блокировки, см. [child-code-login.md](child-code-login.md) |
| `GET /api/me` | Всё для главного экрана: ребёнок, настройки, неделя, темы, наклейки |
| `POST /api/sessions` | Собрать занятие по уроку (`lesson`, `null` — только повторения); 409 для закрытого урока; пустой план, если нечего учить |
| `POST /api/sessions/{id}/answers` | Проверить ответ, начислить монеты |
| `POST /api/sessions/{id}/finish` | Отметить день занятия, вернуть итог |

Все запросы кроме входа идут с `Authorization: Bearer <ключ>`. Ключ хранится в
базе хешем; отключённое из бота устройство получает 401 и экран входа.

## Правила (сервер — источник правды, `backend/app/services`)

- **Календарь** (`core/clock.py`): день и неделя считаются по Тбилиси, неделя с
  понедельника. Системные часы читаются в одном месте, всё остальное получает
  «сейчас» параметром.
- **Сборка занятия** (`learning.py`, правила уроков в `lessons.py`): до 3 новых слов
  урока по порядку из YAML, до 4 повторений (сначала слова урока, потом самые давние
  невыученные из прошлых; сегодня ещё не отвеченные верно). Повтор пройденного урока —
  все его слова плюс 4 старых. Варианты ответа только из темы слова. Слово считается
  введённым в момент сборки занятия.
- **Ответ**: монета только за верный ответ с первой попытки, один раз за шаг и один
  раз за слово в день (повтор урока не платит дважды). Ступень слова растёт не чаще
  раза в день; третья ступень — слово выучено, +5.
  Неверный ответ ничего не отнимает. Повтор с тем же `client_answer_id` возвращает
  прежний результат.
- **Монеты** (`coins.py`): каждая монета — строка леджера, `weeks.coins` — их сумма
  в той же транзакции. Потолок недели: `курс × лимит` монет. Лари: `монеты / курс`,
  округление вниз до 0,1, не больше лимита. «Выплачено» закрывает неделю и
  запоминает курс и лимит на момент выплаты; повторное нажатие ничего не меняет.
  Незакрытая прошлая неделя с монетами показывается в отчёте «к выплате» с отдельной
  кнопкой; новая неделя всё равно начинается с нуля.

## Бот (`backend/bot`)

Команды: `/start`, `/report`, `/progress`, `/settings`, `/code`, `/devices`, `/reset`,
`/addchild Имя`. Кнопки: «Выплачено», «Слова недели», курс (5/10/15/20/30), лимит
(5/10/15/20/30), подсказка кириллицей, «Отключить» устройство. Чужие пользователи
игнорируются; первые родители берутся из `ADMIN_TELEGRAM_IDS`. Если у родителя
несколько детей, бот сначала спрашивает «Кто?». Планировщик внутри процесса бота
шлёт отчёт всем родителям каждого ребёнка в воскресенье 20:00 Asia/Tbilisi.
В базу бот не ходит: всё через `/api/parent/*`, см.
[bot-via-api.md](bot-via-api.md).

## Данные (`backend/app/models`)

`parents` ↔ `children` (много ко многим, у ребёнка код входа), `devices`,
`login_locks`, `topics`,
`words`, `word_progress` (ступень 0–3, дата последнего верного ответа, введено,
выучено), `sessions` (план шагов в JSON), `answers` (ключ идемпотентности),
`weeks`, `coin_ledger`. Модель сразу поддерживает несколько детей и родителей.

## Что изменилось против прежнего поведения

Раньше существовала только статическая страница «Цвета» без сервера: прогресс жил
в браузере, монеты нельзя было проверить, а дни переключались кнопкой. Она осталась
на GitHub Pages как демонстрация. Теперь прогресс, монеты и недели считает сервер,
одно устройство ребёнка привязано к его записи, родитель видит отчёт в Telegram.

## Что осталось за бортом

- Голосовой диалог, распознавание речи, онлайн-оплата, веб-кабинет родителя,
  мультиарендность для школ (вне MVP по заданию).
- Картинки вместо эмодзи: формат `image.kind: file` заложен, самих картинок нет.
- Записи носителя: сейчас звук синтезирован (`make tts`), транскрипции не проверены.
- Живой Telegram не проверялся: нужен `BOT_TOKEN`. Обработчики и планировщик
  проверены без сети.
- Ребёнок заводится командой `/addchild` в боте; в задании способ не был описан.
