# Кабинет родителя: прогресс по темам как Telegram Mini App

Документ отвечает на «как устроено» тому, кто код не писал. Что менялось,
видно в `git log`. Макеты: экран целиком
[parent-cabinet-progress.html](../mockups/parent-cabinet-progress.html), сигнал
«начато» (принят вариант A)
[parent-cabinet-started.html](../mockups/parent-cabinet-started.html).
Как это выглядит для родителя, описано в руководстве, раздел «Кабинет:
прогресс экраном».

## Зачем

Бот хорош для уведомлений и коротких действий и плох для чтения: `/progress`
выдаёт одно сообщение на 20 тем и 232 карточки. Кабинет показывает ту же
картину экраном, внутри Telegram, без второй регистрации и без пароля. Первый
шаг только чтение и только один экран, прогресс по темам; `/progress` в боте
остаётся.

## Как устроено

Кабинет живёт в контейнере бэк-офиса `admin` под префиксом `/cabinet`, со своим
роутером, своей cookie и своим входом; Caddy проксирует `/cabinet/*` туда же,
куда `/admin/*`. В базу кабинет не ходит: он такой же клиент API, как бот, и
читает `/api/parent/*` с общим `BOT_API_TOKEN`, называя родителя в заголовке
`X-Telegram-Id`. Граница доступа остаётся на стороне API (`app/api/deps.py`):
незнакомый Telegram ID даёт 403, чужой ребёнок 404. Никаких новых ручек,
таблиц и секретов.

### Вход

1. Бот при старте ставит постоянную кнопку меню «Кабинет» (`MenuButtonWebApp`)
   и добавляет кнопку «Открыть кабинет» под `/progress` (`bot/keyboards.py`,
   `cabinet_url`, `cabinet_kb`). Telegram принимает для Mini App только https,
   поэтому при `PUBLIC_URL` без https кнопок нет, в лог пишется причина.
2. `GET /cabinet/` без cookie отдаёт страницу-шлюз `cabinet_entry.html`. Её
   скрипт берёт у Telegram подписанные данные `initData` и отправляет их формой
   в `POST /cabinet/session`. В обычном браузере данных нет, и страница остаётся
   на «Откройте из бота».
3. `admin/app/telegram.py` проверяет подпись по `BOT_TOKEN` так, как описано в
   документации Telegram: HMAC-SHA256 от отсортированных полей ключом
   HMAC(«WebAppData», токен). Данные старше часа не принимаются: `initData`
   выдаётся в момент открытия, старые были откуда-то скопированы.
4. Успех: cookie `mziko_cabinet` на 30 дней, путь `/cabinet`, HttpOnly,
   подписана `ADMIN_SESSION_SECRET` с отдельной солью (itsdangerous), и
   редирект на `/cabinet/?in=1`. Метка `in=1` нужна шлюзу: если cookie не
   прижилась, страница показывает «Не получилось войти», а не пробует снова
   по кругу. Неверная подпись даёт 401 с той же страницей.

Отдельного SessionMiddleware для кабинета нет намеренно: на процесс он один,
и он занят cookie владельца по пути `/admin`.

### Страница прогресса

`GET /cabinet/` с cookie (`admin/app/cabinet.py`, `progress`):

- `GET /api/parent/children` даёт детей; 403 означает, что человек не проходил
  `/start`, страница отправляет к боту. Пустой список: «Детей пока нет».
- Ребёнок выбирается параметром `?child=<id>`; чужой или устаревший id тихо
  заменяется первым ребёнком, ошибки нет.
- `GET /api/parent/children/{id}/progress` отдаёт темы. Контракт
  (`app/schemas/parent.py`) для кабинета дополнен: у темы `section` (буквы,
  слоги, слова, из `lessons.section_of`); у слова `last_correct_date`,
  `introduced` и `introduced_on` (показано ли на уроке и когда впервые, из
  `word_progress`); у ответа целиком `lessons_done`, число доигранных до конца
  занятий (`report.lessons_done`, счёт по `sessions.finished_at`). Бот эти
  поля игнорирует.
- `build_sections` собирает модель представления: три раздела в порядке
  приложения; у темы `learned`, `in_work` (показано, но не выучено), два
  процента для полоски (`pct` выученных и `pct_started` выученных вместе с
  теми, что в работе), статус («done», «now» от первого показанного слова,
  пусто) и `idle_days`; у слова ступень и `introduced`. Метка «без
  продвижения» ставится начатой, но не пройденной теме, если 7 и более дней
  назад (`IDLE_DAYS`) был последний верный ответ, а если верных ответов не
  было вовсе, последний первый показ слова. «Сегодня» по календарю Тбилиси.
- Шаблон `cabinet_progress.html` рисует переключатель детей (только при двух и
  больше), вкладки (одна живая, остальные «скоро»), сводку «Выучено N из M
  карточек» со строкой «В работе: N · пройдено уроков: N», разделы и темы.
  Полоски двухслойные (`.tbar.lay`): светлая часть за слова в работе, сплошная
  за выученные, обе от левого края. В раскрытой теме слово, показанное, но
  стоящее на ступени 0, получает метку «показано», не показанные слова бледные
  (`.w.new`) с подписью «Бледные ещё не были на уроках: N». Карточка «Занятий
  пока не было» держится до первого показанного слова, не до первой ступени.
  Тема раскрывается нативным `<details>`, без JS. Недоступный API даёт
  карточку «Не получилось загрузить» и «Повторить» на тот же адрес.

Стили `cabinet.css`: токены дословно из `frontend/src/styles.css`, детали из
макета. Тёмная тема по `prefers-color-scheme`, а если Telegram сообщает свою
схему, `cabinet_base.html` ставит `data-theme` из `Telegram.WebApp.colorScheme`.
Тот же скрипт зовёт `ready()` и `expand()`.

## Тесты

- `admin/tests/test_cabinet.py`: подпись Telegram (верная, чужой токен, пустой
  токен, подмена id, старые данные), шлюз без Telegram и после неудачи, 401 на
  плохую подпись, вход с cookie и список детей, протухшая cookie,
  незарегистрированный, страница с разделами и метками, выбор ребёнка и
  запасной первый, пустой ребёнок, первый день без единого верного ответа
  (считается начатым), нет детей, недоступный API, `build_sections` с метками
  «в работе» и «без продвижения» по дате показа.
- `backend/tests/test_parent_api.py`: `section`, `last_correct_date`,
  `introduced`, `introduced_on` и `lessons_done` в ответе.
- `backend/tests/test_bot.py`: адрес кабинета только для https, кнопка Mini App.

Проверки: `make lint`, `make test`.

## Что изменилось против прежнего поведения

Раньше прогресс был только текстом в боте. Теперь та же информация доступна
экраном внутри Telegram; сообщение `/progress` не изменилось, под ним появилась
кнопка. В API добавлены два поля в существующий ответ, поведение приложения
ребёнка и бэк-офиса не менялось.

## За бортом

- Остальные экраны кабинета: неделя, календарь, выплаты, код и устройства.
  Вкладки стоят на месте с пометкой «скоро».
- Любые действия из кабинета («Выплачено», настройки, перевыпуск кода).
- Локальный запуск кабинета без Telegram: шлюз требует подписанные данные, а
  Telegram открывает Mini App только по https. Проверка локально идёт тестами
  и отрисовкой страниц через тестовый клиент.
- Снимок кабинета для руководства: делается из настоящего Telegram после
  деплоя.
- Имя ребёнка в заголовке окна Mini App: Telegram показывает имя бота.
