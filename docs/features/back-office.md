# Бэк-офис владельца

Отдельный сайт для одного человека, владельца проекта, чтобы видеть родителей,
их детей и продвижение каждого ребёнка. Только чтение: ни одной кнопки, которая
что-то меняет. Вход через Google, пускают одну заранее известную почту.

Макеты: [список родителей](../mockups/admin-parents.html),
[карточка родителя](../mockups/admin-parent-card.html),
[вход](../mockups/admin-login.html).

## Как устроено

Бэк-офис живёт в своём контейнере `admin` и устроен как бот: в базу не ходит,
стучится в API по общему секрету. У API появилась группа ручек «только чтение»
`/api/admin/*`, закрытая заголовком `Authorization: Bearer <ADMIN_API_TOKEN>`.
Caddy отдаёт бэк-офис по адресу `/admin/` на том же домене, что приложение, так
что сертификат и DNS не меняются, а у Google один адрес возврата; голый `/admin`
перенаправляется на `/admin/`, иначе он достался бы оболочке приложения. Приложение
(PWA) держит `/admin` в исключениях сервис-воркера (`navigateFallbackDenylist` в
`frontend/vite.config.ts`): иначе браузер, где детское приложение уже открывали,
показывал бы на `/admin/` экран ребёнка вместо бэк-офиса.

Внутри контейнера маленькое приложение на FastAPI: страницы собираются на
сервере из шаблонов Jinja2, стили и палитра те же, что у детского приложения,
но без холмов и маскота. React не используется намеренно: три экрана только
читают, а без сборки, токена в браузере и CORS движущихся частей меньше.

## Вход

Единственная кнопка «Войти через Google». Браузер уходит на выбор аккаунта
Google и возвращается на `/admin/login/callback` с одноразовым кодом; сервер
обменивает его на почту, предъявив идентификатор и секрет OAuth-клиента.
Если почта подтверждена Google и совпадает с `ADMIN_EMAIL` без учёта регистра,
ставится подписанная cookie `mziko_admin` на 14 дней (`ADMIN_SESSION_SECRET`,
только для пути `/admin`, `Secure` при `https`). Иначе:

- другая почта — карточка «Доступ не выдан» с этой почтой и кнопкой войти
  другим аккаунтом (выбор аккаунта у Google принудительный);
- отмена или ошибка на стороне Google — «Вход не завершён», «Попробовать снова»;
- cookie, которую сервер уже не читает (истёк срок, сменился секрет) — страница
  входа со строкой «Сессия закончилась»;
- «Выйти» стирает cookie.

Паролей, регистрации и кодов из приложения-аутентификатора нет.

## Экраны

**Список родителей** `/admin/`. Таблица: родитель (имя или «— без имени»,
Telegram ID), последнее занятие, дети построчно (имя · выучено слов · когда был
урок), эта неделя (лари крупно, монеты мелко, метка «потолок»), прошлая неделя
(«выдано», «к выдаче» или прочерк), регистрация. Деньги по родителю не
складываются: у детей разные ставки, каждая строчка ребёнка живёт отдельно.
Счётчик, поиск по имени родителя, ребёнка и Telegram ID, сортировка по
заголовкам (по умолчанию свежие занятия сверху), «Показать ещё 50» — на
клиенте поверх уже отрендеренной таблицы. На узком экране таблица едет вбок,
колонка родителя прибита слева.

**Карточка родителя** `/admin/parents/<id>`. Блок родителя и по разделу на
каждого ребёнка: код входа с пином, ставка, потолок, подсказки; прогресс по
темам полосками («пройдена», «в работе», «не начата»); календарь занятий за
четыре недели (пройденный день, недоигранный, будущий, сегодня) со сводкой
«уроков за 4 недели» и «верно с первой попытки»; последние шесть недель с
монетами и статусом («открыта» только у текущей недели по дате понедельника);
устройства с последним заходом и меткой «отозвано». Каждый блок показывает
своё «пусто», поэтому только что добавленный ребёнок выглядит честно.
Неизвестный id — «Родитель не найден», недоступный API — «Повторить».

«Сегодня» и относительные даты считаются по календарю Asia/Tbilisi, как и всё
в продукте. «Последнее занятие» — день начала урока, включая недоигранные.

## Ручки API

| Ручка | Что отдаёт |
|---|---|
| `GET /api/admin/parents` | Все родители, новые сверху, у каждого ребёнка: выучено слов, последний урок, недели текущая и прошлая, признак потолка |
| `GET /api/admin/parents/{id}` | Родитель и полная карточка каждого ребёнка: код входа, настройки, темы с признаком «начата», дни занятий за 28 дней, доля верных первых попыток, шесть недель, устройства; 404 для чужого id |

Пагинации и поиска на сервере нет: родителей десятки, список отдаётся целиком.
Новых таблиц и миграций нет, расчёты лари и прогресса переиспользуют код
ботовских отчётов.

## Настройка

Переменные в `.env` (см. `.env.example`, блок «Back office»): `ADMIN_EMAIL`,
`ADMIN_API_TOKEN`, `ADMIN_SESSION_SECRET`, `GOOGLE_CLIENT_ID`,
`GOOGLE_CLIENT_SECRET`. OAuth-клиент типа «веб-приложение» создаётся в Google
Cloud Console с адресом возврата `<PUBLIC_URL>/admin/login/callback`; для
локальной проверки добавляется `http://localhost:8080/admin/login/callback` и
бэк-офис запускается `PUBLIC_URL=http://localhost:8080 make admin`.

Образ `mziko-admin` собирается и раскатывается тем же workflow, что остальные
(см. [ci-cd.md](ci-cd.md)). Проверки: `make lint`, `make test`.

## Что изменилось против прежнего поведения

Раньше владелец видел данные только через бот, от имени родителя, и только про
своих детей. Теперь есть обзор всех родителей и детей в одном месте. Поведение
приложения и бота не менялось; в API добавлены только ручки чтения и один
секрет.

## За бортом

- Любые действия: правка настроек ребёнка, выплаты, перевыпуск кода, отзыв
  устройств. Это по-прежнему делает родитель в боте.
- Имя родителя: поле в базе есть, но бот его не заполняет, поэтому в списке у
  большинства будет «— без имени». Отдельный шаг, если понадобится.
- Второй администратор, роли, журнал входов.
- Невыплаченные недели старше прошлой в списке (видны в карточке).
- Вход без секрета клиента через подписанный билет Google в браузере: возможен,
  но движущихся частей не меньше.
