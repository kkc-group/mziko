# Мзико: стиль и тон

Этот файл — источник правды о том, как выглядит и звучит Мзико. Он нужен,
чтобы макет и UI-код делались без чтения `frontend/src/styles.css` и трёх
мегабайт старых макетов: токены, каркас, размеры и тексты собраны здесь.
Нет чего-то здесь — смотри эталонный макет своей семьи (таблица ниже), а не
все макеты подряд.

Скил правится вместе с фичей: изменился токен, примитив, текст бота или
правило — правится и этот файл, в той же ветке, до мержа.

## 1. Токены — дословно

Источник: `frontend/src/styles.css:2-24`. Те же значения продублированы в
`admin/app/static/cabinet.css`, `admin/app/static/admin.css`,
`site/template.html` — при правке токена меняются все четыре файла и этот.

Блок для `<style>` макета, копировать как есть:

```css
/* tokens: verbatim from frontend/src/styles.css */
:root {
  --bg: #e4f1ff; --surface: #ffffff; --ink: #2a1a48; --muted: #6a5e86; --line: #d3e2f4;
  --grape: #5b2e8c;
  --pom: #e23b55; --pom-dark: #b8243d; --pom-soft: #ffe3e8;
  --sun: #ffc531; --sun-dark: #e0a300;
  --mint: #1fb386; --mint-dark: #13875f; --mint-soft: #ddf7ee;
  --hill1: #a4db86; --hill2: #72c36b;
  --blob-edge: rgba(42, 26, 72, 0.14);
  --word-color: var(--grape);
  --safe-top: env(safe-area-inset-top, 0px); --safe-bottom: env(safe-area-inset-bottom, 0px);
  --safe-left: env(safe-area-inset-left, 0px); --safe-right: env(safe-area-inset-right, 0px);
}
@media (prefers-color-scheme: dark) { :root:not([data-theme='light']) {
  --bg: #131634; --surface: #1e2250; --ink: #f3efff; --muted: #aba5d3; --line: #2f3572;
  --mint-soft: #113d35; --pom-soft: #44182a; --hill1: #27523a; --hill2: #1c4030;
  --blob-edge: rgba(255, 255, 255, 0.22); --word-color: var(--sun);
} }
:root[data-theme='dark'] {
  --bg: #131634; --surface: #1e2250; --ink: #f3efff; --muted: #aba5d3; --line: #2f3572;
  --mint-soft: #113d35; --pom-soft: #44182a; --hill1: #27523a; --hill2: #1c4030;
  --blob-edge: rgba(255, 255, 255, 0.22); --word-color: var(--sun);
}
```

Что чем является:

- `--grape` — бренд, заголовки, грузинское слово в светлой теме. Не меняется в тёмной.
- `--pom` / `--pom-dark` — главная кнопка «Играть», неверный ответ, ошибка.
- `--mint` / `--mint-dark` — верный ответ, «Дальше», прогресс.
- `--sun` / `--sun-dark` — монеты, кнопка «Послушать», грузинское слово в тёмной теме.
- `--*-soft` — фон тостов и мягких плашек той же семантики.
- `--hill1/2` — декоративные холмы внизу детских экранов, `--blob-edge` — кромка цветного пятна под картинкой слова.
- Белый текст на цветных кнопках — `#fff` (в коде так и захардкожено, переменной нет).

Радиусы и тени в переменные не вынесены. Принятые значения: карточка 24px,
плитка 26px, кнопка «Играть» 22px, плитки-кнопки 14–16px, карточки кабинета и
админки 16px, круглые элементы 50%. Тень — только «псевдо-3D» под кнопкой:
`box-shadow: 0 Npx 0 var(--x-dark)` или `0 5px 0 var(--line)` у нейтральных
плиток. Размытых теней в продукте нет.

## 2. Шрифты

```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Nunito:wght@500;700;800;900&family=Noto+Sans+Georgian:wght@600;800&display=swap" rel="stylesheet">
```

```css
body { font-family: 'Nunito', system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif; font-size: 17px; line-height: 1.45; color: var(--ink); background: var(--bg); }
.ka { font-family: 'Noto Sans Georgian', 'Sylfaen', 'DejaVu Sans', sans-serif; font-weight: 800; }
```

Любой грузинский текст — в `.ka`. Всегда. Кириллическая транслитерация идёт
вторым слоем: мельче (`.tr` 18px) и `--muted`. Порядок «сначала оригинал,
потом подсказка» не нарушается.

Подключать Google Fonts в макет обязательно там, где смотрим на буквы, слова
или кнопки; в макетах таблиц и списков допустим системный фолбэк, но это
называется в отчёте.

## 4. Каркас макета

Макет — одна HTML-страница-галерея, самодостаточная (без сборки; сеть только
на Google Fonts). Структура:

1. `<h1>` — название задачи. `<p class="lead">` — «Как сейчас» со ссылками
   `файл:строка` на текущий код.
2. Для каждого состояния: `<h2>N · Название состояния</h2>`, `<p class="lead">`
   с физикой решения (что появилось, что нажато, почему), затем
   `<figure><figcaption>…</figcaption><div class="fw"><div class="dev phone">…</div></div></figure>`.
   Светлая и тёмная тема рядом, сеткой `.cols`.
3. `<h2>Решения в спорных местах</h2>` — `<ul class="lead">` с пунктами вида
   `<b>Заголовок.</b> Обоснование`. Один пункт обязателен: **что уступает при
   нехватке места**.
4. `<h2>Чего нет на макете</h2>` — что сознательно не нарисовано и почему.
5. Замеченный существующий баг помечается: «не часть этой задачи — показано,
   чтобы не было сюрпризом».

Рамка телефона (из `home-menu.html:161-171`):

```css
.mk { max-width: 1440px; margin: 0 auto; padding: 24px; }
.cols { display: grid; grid-template-columns: repeat(auto-fit, minmax(340px, 1fr)); gap: 24px; }
.dev.phone { width: 410px; height: 864px; border: 10px solid #0d0d12; border-radius: 54px; overflow: hidden; position: relative; --safe-top: 47px; --safe-bottom: 34px; background: var(--bg); }
.fw { width: 328px; height: 691px; }      .fw .phone { transform: scale(0.8); transform-origin: top left; }
.fw.sm { width: 246px; height: 519px; }   .fw.sm .phone { transform: scale(0.6); }
```

Данные на макете — правдоподобные, но выдуманные; темы и слова берутся из
`content/topics/*.yaml`, а не придумываются. Эмодзи — инлайн-символ в
`<span class="emoji" role="img" aria-hidden="true">🍎</span>`; приложение
рисует их из Twemoji, макет — системным шрифтом, и это допустимая разница.
Картинки как `data:` — только когда макет и есть сверка картинок.

### Только изменяемая часть

Рисуется то, что меняется, со всеми состояниями **этой части**. Остальной
экран — рамка-контекст, а не копия приложения:

```css
.ctx { background: var(--line); opacity: .55; border-radius: 16px; min-height: 48px;
       display: grid; place-items: center; color: var(--muted); font-size: 13px; }
```

Блок `.ctx` подписывается тем, что он замещает: «шапка — как сейчас»,
«список уроков — как сейчас». Шапка, меню, холмы и соседние карточки, которые
задача не трогает, остаются такими блоками. Целиком рисуется только новый
экран, которого раньше не было, и это должно быть сказано в задаче явно.

**Закон нажатия** (`styles.css:39-59`, `docs/features/button-feedback.md`).
Кнопка с тенью вдавливается на 2/3 тени, треть остаётся: `.play` уходит на
4px (тень 6→2), `.next`, `.tile`, `.opt .ans`, `.speak` — на 3px, `.mini-play`
— на 2px. Нажатие 80мс, отпускание 120мс. Плоские кнопки сжимаются до 96% и
заливаются `--line`. Кнопка с тенью — настоящее действие; без тени — навигация.

**Серый цвет — только `:disabled`**, то есть «нажать нельзя вообще». Во
время запроса кнопка не сереет: остаётся утопленной и цветной, показывает
`BusyLabel` (спиннер + «Открываю…», через 3 с «Ещё чуть-чуть…»), а всё
остальное накрывает `.scrim`. Ошибка сети снимает пелену и показывает
`.notice`.

Анимации: `bounce` 0.6s (маскот), `pulse` 0.5s×2 (озвучка), `checkPop` 260ms
(галочка и крестик), `shake` 0.35s (неверный ответ, неверный код), `rot` 0.8s (спиннер),
`flyCoins` — до 6 монет `₾` летят к копилке. Всё глушится при
`prefers-reduced-motion`, нажатое положение при этом остаётся.

Кабинет и админка: скелетон загрузки `.sk`, чип `.chip`, блок сообщения
`.msgc` (пусто, ошибка, нет доступа `.deny`), кнопка `.retry` 44px, строка
темы `.trow`. Тени-нажатия там нет.

Кабинет, переключатель положений `.seg` (первое действие в кабинете, эталон
`docs/mockups/parent-topic-access.html`): три кнопки в одну строку, не ниже
44px, на подложке `--line`; выбранная — `--surface` с рамкой `--word-color`.
Вокруг него форма `.acc` с подписью `.acc-h`, пояснением `.acc-note` и ошибкой
`.acc-err` на `--pom-soft`. Нажатие сохраняет сразу, без кнопки «Сохранить».
Метки ручного положения в строке темы — `.chip.acc-on` (`--mint-soft`) и
`.chip.acc-off` (`--pom-soft`), текст `--ink`; они идут первыми в `.stale`.

## 6. Типографика и размеры

- Тело 17px / 1.45 (кабинет 15px). Заголовки: `.hi h1` 34px (до 2 строк),
  `.topbar h1` 30px, `.done-screen h2` 30px, `.cur-t b` 26px, `.card h2` 24px.
- Крупная грузинская буква/слово в уроке: `.word .ka` 54px, на узком экране
  42px. Буква на плитке `.glyph.l` — 1.25 от размера плитки. Слово на плитке
  ужимается по длине через `--len`, не переносится.
- Картинка опорного слова на плитке буквы — 30px при букве 80px, в альбомной
  ориентации 24px: «плитка как прежняя плюс наклейка».
- Размеры эмодзи по месту: 96px в круге карточки, 64px в плитке, 40px в
  иконке темы, 34px в якоре буквы, 28px в наклейке.
- Кириллица длиннее латиницы на 10–15%; худший реальный случай — ჭიანჭველა
  (муравей): карточка после ответа видна около секунды, поэтому подсказки на
  ней нет.
- Ширина контента детского приложения 540px, safe-area учитывается в `.wrap`,
  `.lesson`, `.login`, `.sheet`, `.notice`, `.topbar`.

## 7. Тон текстов

**Ребёнку — на «ты», коротко, глагол действия.** Кнопки называются «Играть»
и «Повторить», не «Начать урок». Дословно из `frontend/src`:

- «Поиграем, {имя}?» — приветствие на главном.
- «Новая буква!» / «Новое слово!» — заставка перед интро.
- «Буква выучена! +N 🪙» / «Слово выучено! +N 🪙» — награда.
- «На сегодня всё! Завтра новые слова» — плавающее сообщение (`.notice`) при
  выходе из занятия, когда лимит дня исчерпан.
- «На сегодня всё!» / «Новые задания — завтра. А пока можно повторить» (или,
  без слов на повтор, просто «Новые задания — завтра») — карточка на «Сегодня»,
  когда играть больше нечего ни в одном разделе; другой текст той же мысли,
  на другом месте экрана.
- «На сегодня готово» — мятная строка раздела на «Сегодня», который уже взял
  и прошёл сегодня новую тему; следующая откроется завтра.
- «Все буквы пройдены!» (и так же для слогов, слов) — мятная строка раздела,
  пройденного целиком.
- «Тренировка» / «Повторим знакомое» — строка на «Сегодня» с викториной из
  старых невыученных слов, отдельно от урока конкретного раздела.
- «Всё закреплено!» — повторять нечего.
- «Нет связи. Проверь интернет и попробуй ещё» — оффлайн.
- «Этот урок пока недоступен» — блокировка (тост при попытке начать запертый
  урок, без срока: причина может быть и в порядке тем). Подпись под замком темы — «завтра» (раздел уже взял сегодня новую
  тему), «после «Цвета»» (не пройдена предыдущая тема раздела) или «закрыли
  родители» (тему закрыл родитель в кабинете; вид замка тот же, отличается
  только подпись).
- «Пока всё» / «{раздел} · темы закрыли родители» — строка раздела на «Сегодня»,
  когда в нём остались только закрытые родителем темы: `.lsn.lock` с замком
  справа, не мятная — мятная строка значит «готово», а здесь закрыто.
- «Каждый день — одна новая тема из каждого раздела» — подсказка маскота на
  экране «Путь».
- «Открываю…» → «Ещё чуть-чуть…» — занятая кнопка.
- «Нажми на цветную наклейку — услышишь слово» — подсказка на экране «Наклейки».
- «Выучи слово — наклейка станет цветной» — та же подсказка, пока выученных нет.

**Родителю — на «вы», деловито, всегда с следующим шагом.** Эмодзи только
как данные (иконка темы, слова), не как украшение. Про деньги и риски —
прямо. Дословно из `backend/bot/texts.py`:

- «Привет! Я Мзико, бот для родителей.»
- «Сейчас один раз заведём первого ребёнка. Следующих детей добавите потом
  одной командой, я её покажу в конце.»
- «Два вопроса, и готово. Как вас зовут?»
- «Кнопка «Кабинет» слева от строки ввода — прогресс ребёнка экраном: темы,
  слова, занятия, монеты.»
- «Готово! Вы в Мзико как **{имя}**, добавил: **{ребёнок}**.»
- «Выдайте наличные и нажмите «Выплачено».»
- «Отключить {имя} от вас? Прогресс, код и устройства сохранятся.»
- «Длинновато: {N} знаков, а помещается 100. Напишите покороче.»

Тексты в макете цитируются из кода, где они уже есть, и пишутся в этом же
тоне, где их ещё нет. Новая сущность на макете — незаметно принятое
продуктовое решение: без задачи не заводится.

Продуктовые принципы, которые макет не нарушает: картинка не выдаёт ответ
(буква без подходящего эмодзи оставляет угол пустым); главный экран отвечает
на один вопрос — во что играть сейчас; монеты сгорают в понедельник, наклейки
остаются навсегда.

## 8. Состояния, которые обязаны быть у изменяемой части

Пусто · загрузка (детское — спиннер `rot` или утопленная кнопка с `.scrim`;
кабинет и админка — скелетон `.sk`) · ошибка / оффлайн (тост или `.msgc` с
кнопкой «Повторить») · переполнение и длинный текст (много тем, ჭიანჭველა,
имя ребёнка в две строки) · тёмная тема рядом со светлой. Для урока — ещё
альбомная ориентация iPad. Для админки — узкое окно 640px, «доступ не выдан»,
«поиск ничего не нашёл». Макет, где всё влезло и всё заполнено, — картинка, а
не проверка.

## 9. Для UI-кода: тон разработки

- Цвет только через `var(--…)`; нового токена без правки всех четырёх копий и
  этого файла не бывает.
- Новая кнопка — один из классов раздела 5 и закон нажатия из него. Новый
  класс кнопки заводится, когда ни один существующий не подходит, и это
  сказано в отчёте.
- Грузинский текст — `.ka`; транслитерация — второй слой, `--muted`.
- Эмодзи в приложении — через компонент `Emoji` (Twemoji), не символом.
- Анимация — только с `prefers-reduced-motion`-глушением; оно общее в
  `styles.css`, новые keyframes под него попадают сами.
- Компонент по принятому макету — дословно по макету; отличие называется в
  `docs/features/<feature>.md` словами.

## 10. Известные несогласованности — не чинить попутно

Они есть, о них известно, и правятся они отдельным шагом по явному «да», а не
по дороге:

- токены живут в четырёх копиях без общего источника; у `admin.css` и
  `cabinet.css` нет `--hill1/2` и `--blob-edge`;
- радиусы и тени не токенизированы, у визуально одинаковых карточек они
  разные (16px в кабинете, 22–26px в детском);
- кабинет и админка объявляют Nunito, но не подключают Google Fonts, поэтому
  показывают системный шрифт;
- PWA-манифест знает только светлую тему, `<meta theme-color>` — обе;
- `.msgc` в макетах админки и кабинета разошёлся по отступам (28 против 48px);
- ручного переключателя темы нет нигде, кабинет берёт тему из Telegram,
  остальное — из системы;
- новый эмодзи интерфейса (не из `content/topics/*.yaml`) нужно вручную
  добавить в `INTERFACE_EMOJI` (`scripts/fetch_twemoji.py`), иначе `fetch_twemoji`
  его не скачает, и `<Emoji>` тихо откатится на системный шрифт (404 картинки);
- `today_lesson` в `GET /api/me` больше не читается фронтом (главный экран
  сам считает, что играть сегодня, по `topics`/`lessons`) — поле осталось на
  сервере ради обратной совместимости, не как источник правды для экрана;
- на «Наклейках» счётчик темы всегда «N слов» (`ProgressMap.tsx`, `wordsW`),
  даже у букв и слогов — в отличие от «Пути» и «Сегодня», которые считают в
  единице своего раздела (`count()`, `plural()`);
- `BurgerIcon` в `Icons.tsx` и `.lsn.fold` в `styles.css` не используются;
- эталон кабинета `parent-cabinet-progress.html` отстал от кода: строка темы там
  `button.trow.open` вместо `<details>`, нет «в работе» и слоёной полоски;
- нейтральный серый чип в кабинете называется `.chip.open` — рядом с доступом
  «Открыта» имя путает, поэтому чипы доступа названы `acc-on` / `acc-off`;
- на 320px чип «9 дн. без продвижения» ломается на две строки внутри себя;
- большая карточка «На сегодня всё! Новые задания — завтра» на «Сегодня» не
  знает про закрытые родителем темы: если играть нечего только из-за них,
  «завтра» неверно (строки разделов под ней при этом честные — «Пока всё»).
