# Мзико — приложение для изучения грузинского для детей

Задание на реализацию MVP. Визуальный референс — `docs/prototype.html` (кликабельный прототип, открыть в браузере). Внешний вид, тексты интерфейса и механику игр повторяй по нему.

## 1. Цель

Веб-приложение (PWA) для ребёнка 7 лет с нулевым грузинским. Ребёнок учит слова по карточкам (картинка + звук), получает монеты, раз в неделю монеты по курсу превращаются в лари, которые родитель выдаёт наличными. Родитель управляет всем через Telegram-бот.

Сейчас пользователь один ребёнок (Сандро), но модель данных сразу поддерживает несколько детей и несколько родителей — позже продукт может пойти в школу.

**Вне рамок MVP:** голосовой диалог, распознавание речи, онлайн-оплата, веб-кабинет родителя, мультиарендность для школ.

## 2. Стек

- **Backend:** Python 3.12, FastAPI, SQLAlchemy 2 (async) + asyncpg, Alembic, Pydantic v2.
- **БД:** PostgreSQL 16.
- **Бот:** aiogram 3, отдельный процесс, общий пакет моделей с API.
- **Планировщик:** APScheduler внутри процесса бота (еженедельный отчёт).
- **Frontend:** React + TypeScript + Vite, `vite-plugin-pwa`. Без UI-библиотек, стили на CSS-переменных, как в прототипе. Шрифты: Nunito + Noto Sans Georgian.
- **Деплой:** docker-compose: `db`, `api`, `bot`, `web` (Caddy отдаёт статику фронта, проксирует `/api` и `/media`, HTTPS).
- **Часовой пояс всей бизнес-логики:** `Asia/Tbilisi`. Неделя — понедельник–воскресенье.

Структура репозитория:

```
backend/app/{api,models,services,schemas,core}/
backend/bot/
backend/alembic/
backend/tests/
content/topics/*.yaml
media/audio/<topic>/<slug>.mp3
frontend/
docs/prototype.html
docker-compose.yml
```

## 3. Темы и контент

Контент хранится в YAML в репозитории и загружается командой `python -m app.seed` (идемпотентный upsert по `topic.slug` + `word.slug`). Порядок слов в YAML = порядок изучения.

Формат:

```yaml
slug: colors
title_ru: Цвета
title_ka: ფერები
icon: "🎨"
order: 2
words:
  - slug: red
    ka: წითელი
    tr: цители        # кириллическая подсказка
    ru: красный
    image: {kind: color, value: "#E53935"}
```

`image.kind`: `emoji` (value — эмодзи), `color` (value — hex, рисуется кругом-кляксой этого цвета), `file` (value — путь в `/media/images`, на будущее).

### Звук

- Файл на каждое слово: `media/audio/<topic>/<slug>.mp3`. Финальные записи сделает носитель.
- Сделай скрипт `scripts/gen_tts.py`, который генерирует временные файлы через Azure TTS (голос `ka-GE`, ключ из env), пропуская уже существующие файлы, чтобы записи носителя не перезатирались.
- Если файла нет, фронт использует `speechSynthesis` с fallback на кириллическую подсказку голосом `ru` — как в прототипе.
- Звук слова проигрывается автоматически при показе карточки и по кнопке-динамику; предзагружай аудио всех слов сессии при её старте.

## 4. Логика обучения (сервер — источник правды)

Прогресс по слову: `stage` 0–3, `last_correct_date`, `introduced`, `learned_at`.

**Сборка сессии** (`POST /api/sessions` с `topic_slug`):
1. Новые: до 3 ещё не введённых слов выбранной темы по порядку.
2. Повторение: до 4 слов из **любых** тем, где `introduced = true`, `stage < 3` и `last_correct_date < сегодня`; приоритет — самые давние.
3. Шаги: сначала карточки знакомства с новыми словами, затем перемешанный квиз: каждое новое слово — «Послушай и найди»; каждое слово на повторении — случайно «Послушай и найди» или «Вспомни слово».
4. Если нет ни новых, ни повторений — сервер возвращает пустой план, фронт показывает «На сегодня всё! Завтра новые слова».

**Типы шагов:**
- `intro` — картинка, слово, подсказка, звук, кнопка «Дальше». Помечает слово `introduced`.
- `listen` — звучит слово, выбрать из 4 картинок. Дистракторы берутся **из той же темы**, что и правильное слово (для цветов — только цвета).
- `recall` — картинка, выбрать из 3 грузинских слов, у каждого варианта своя кнопка звука. Дистракторы — введённые слова той же темы, иначе любые слова той же темы.

Варианты ответа генерирует сервер. Правильный ответ приходит на клиент (офлайн-проверка не нужна, но начисление — только сервер).

**Ответ** (`POST /api/sessions/{id}/answers`, тело: `step_index`, `word_slug` выбранного, `attempt`, `client_answer_id` — UUID для идемпотентности):
- Верно с первой попытки → +1 монета. Если `last_correct_date < сегодня` → `stage += 1`, `last_correct_date = сегодня`.
- Когда `stage` стал 3 → слово выучено, +5 монет, `learned_at = now`.
- Неверно → монеты не начисляются, штрафов нет, `stage` не меняется. Ребёнок пробует снова.
- Начисление обрезается недельным лимитом: монет за неделю не больше `rate × cap_lari`.
- Повторная отправка с тем же `client_answer_id` возвращает прежний результат без повторного начисления.
- Ответ сервера: `correct`, `coins_gained`, `word_learned`, `week_coins`, `week_lari`.

**Завершение сессии** (`POST /api/sessions/{id}/finish`) отмечает день занятия (для звёздочек недели и отчёта).

## 5. Монеты, недели и выплаты

- Таблица `weeks`: `child_id`, `week_start` (понедельник), `coins`, `status` (`open` / `paid`), `paid_at`, `lari_paid`, `rate_snapshot`, `cap_snapshot`.
- Все начисления пишутся в `coin_ledger` (child, week, amount, reason: `answer` / `word_learned`, ссылка на ответ). `weeks.coins` — сумма по леджеру, обновляется в той же транзакции.
- Настройки ребёнка: `rate` (монет за 1 ₾, по умолчанию 10), `cap_lari` (по умолчанию 15), `show_hint` (по умолчанию true).
- Лари = `min(coins / rate, cap)`, округление до 0,1 ₾ вниз.
- «Выплачено» закрывает неделю (`paid`), сохраняет сумму и снимки курса/лимита. Копилка на экране ребёнка показывает монеты текущей открытой недели. Если неделя закончилась, а выплату ещё не отметили, новая неделя всё равно начинается с нуля, а старая остаётся `open` в отчёте как «к выплате».

## 6. Авторизация

- **Родитель:** Telegram user id в таблице `parents`. Первый родитель задаётся через env `ADMIN_TELEGRAM_IDS`. Бот игнорирует чужих.
- **Ребёнок/устройство:** родитель в боте делает `/pair` → бот выдаёт одноразовую ссылку `https://<host>/pair/<code>` (живёт 15 минут). Открытие ссылки на iPad создаёт токен устройства (длинный случайный, хранится хешем) и кладёт его в `localStorage`. Все запросы фронта идут с `Authorization: Bearer <token>`. Логина и паролей у ребёнка нет.
- `/devices` в боте — список устройств с кнопкой «Отключить».

## 7. API (минимум)

```
POST /api/pair/{code}                 → {device_token, child}
GET  /api/me                          → ребёнок, настройки, неделя (coins, lari, дни занятий), темы с прогрессом, наклейки
POST /api/sessions {topic_slug}       → {session_id, steps[]}
POST /api/sessions/{id}/answers       → результат ответа
POST /api/sessions/{id}/finish        → итог сессии
GET  /media/...                       → аудио (Caddy)
```

## 8. Frontend (по прототипу)

**Главный экран:** Мзико с приветствием «გამარჯობა!», копилка (монеты и «это N ₾ на сладости»), 7 кружков недели (звёздочка за день с занятием), **плитки тем** («Первые слова» 🐶, «Цвета» 🎨) с прогрессом «выучено X из Y» — нажатие запускает сессию по теме. Ниже — наклейки: выученные слова цветные, остальные серые. Для цветов наклейка — цветной кружок.

**Занятие:** полноэкранное; сверху крестик, прогресс-бар, мини-копилка. Шаги `intro` / `listen` / `recall` как в прототипе. Верно — зелёная подсветка, прыжок Мзико, монеты летят в копилку, тост «Молодец! +1 🪙» / «Слово выучено! +6 🪙». Неверно — красная тряска, тост «Почти! Попробуй ещё», вариант блокируется.

**Итог:** «Ура, занятие готово!», монеты за сессию, новые наклейки, кнопка «Домой».

Требования: крупные зоны нажатия (минимум 56 px), работа на iPad в портретной и альбомной ориентации и на телефоне, светлая/тёмная тема, `prefers-reduced-motion`, safe-area-инсеты, PWA-манифест с иконкой Мзико для «Добавить на экран Домой». Ответы отправляются на сервер; при сетевой ошибке — повтор с тем же `client_answer_id`.

## 9. Telegram-бот

- `/start` — приветствие и меню.
- `/report` — отчёт текущей недели (формат как во вкладке «Родитель» прототипа): дни занятий из 7, выученные слова с эмодзи, монеты → лари, пометка о лимите, незакрытые прошлые недели.
- **Еженедельно, воскресенье 20:00 Asia/Tbilisi** — тот же отчёт всем родителям ребёнка с inline-кнопками «Выплачено» и «Слова недели».
- «Выплачено» — идемпотентно закрывает неделю, редактирует сообщение: «✅ Выплачено N ₾».
- `/settings` — inline-кнопки: курс (5/10/15/20/30 монет за ₾), лимит (5/10/15/20/30 ₾), подсказка кириллицей вкл/выкл.
- `/pair`, `/devices` — см. раздел 6.
- `/progress` — прогресс по темам и словам (●●○).

## 10. Тесты и качество

- pytest + testcontainers (PostgreSQL). Обязательно покрыть: рост `stage` только раз в день; +5 за выученное слово; обрезку по лимиту; идемпотентность ответа; сборку сессии (новые из темы, повторения из всех тем, дистракторы из той же темы); закрытие недели и границы недели по Тбилиси; повторное «Выплачено».
- Для тестов времени — инъекция «сейчас» через зависимость, без `datetime.now()` в бизнес-логике.
- ruff + mypy для backend, eslint + tsc для frontend.
- `make dev` поднимает всё локально с seed-данными; README с шагами деплоя.

## 12. Критерии готовности

- На iPad: привязка по ссылке из бота → иконка на экране → занятие по «Первым словам» и по «Цветам» проходит как в прототипе, со звуком.
- Слово становится выученным только после верных ответов в 3 разных дня; монеты и лари в копилке совпадают с отчётом в боте.
- В воскресенье в 20:00 приходит отчёт; «Выплачено» обнуляет копилку новой недели и не срабатывает дважды.
- Все тесты зелёные, `docker compose up` на чистом сервере поднимает рабочую систему.
